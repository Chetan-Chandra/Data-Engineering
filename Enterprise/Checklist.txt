For a fully isolated Canam Airflow Sandbox, I would execute it in this order. The commands below assume:

GCP project: prj-n-cdp-ingestion
Region: northamerica-northeast1
Sandbox GCS DAG bucket: bkt-prj-n-cdp-ingestion-airflow_dag-sandbox
Sandbox GCS log bucket: bkt-prj-n-cdp-ingestion-airflow_log-sandbox
Sandbox namespace: airflow-sandbox
Sandbox Artifact Registry repo: airflow-sandbox

Important: Some commands use placeholder values such as <EXISTING_GKE_CLUSTER>, because those must match Canam's actual infrastructure. Don't run those until we identify the existing values.

Canam Airflow Sandbox — Execution Order
1. Set GCP project
gcloud config set project prj-n-cdp-ingestion

Verify:

gcloud config get-value project
2. Identify existing TEST infrastructure

Before creating anything, get:

gcloud container clusters list
gcloud sql instances list
gcloud iam service-accounts list
gcloud artifacts repositories list --location=northamerica-northeast1
gcloud storage buckets list

Also identify the existing Kubernetes namespaces:

kubectl get namespaces

And existing Airflow deployments:

kubectl get deployments -A | grep -i airflow

Services:

kubectl get services -A | grep -i airflow

Helm releases:

helm list -A

Do not create sandbox resources until you know these values.

3. Create sandbox GCS DAG bucket

If not already created:

gcloud storage buckets create gs://bkt-prj-n-cdp-ingestion-airflow_dag-sandbox \
  --project=prj-n-cdp-ingestion \
  --location=northamerica-northeast1

Verify:

gcloud storage ls gs://bkt-prj-n-cdp-ingestion-airflow_dag-sandbox
4. Create sandbox GCS log bucket
gcloud storage buckets create gs://bkt-prj-n-cdp-ingestion-airflow_log-sandbox \
  --project=prj-n-cdp-ingestion \
  --location=northamerica-northeast1

Verify:

gcloud storage ls gs://bkt-prj-n-cdp-ingestion-airflow_log-sandbox
5. Create sandbox Artifact Registry repository
gcloud artifacts repositories create airflow-sandbox \
  --repository-format=docker \
  --location=northamerica-northeast1 \
  --description="Canam Airflow Sandbox images"

Verify:

gcloud artifacts repositories list \
  --location=northamerica-northeast1
6. Create sandbox GCP runtime service account
gcloud iam service-accounts create sa-kubtogcp-sandbox \
  --display-name="Canam Airflow Sandbox GKE"

The resulting identity will be:

sa-kubtogcp-sandbox@prj-n-cdp-ingestion.iam.gserviceaccount.com

Verify:

gcloud iam service-accounts list
7. Give sandbox runtime SA access to sandbox DAG bucket

Start with object-level access:

gcloud storage buckets add-iam-policy-binding \
  gs://bkt-prj-n-cdp-ingestion-airflow_dag-sandbox \
  --member="serviceAccount:sa-kubtogcp-sandbox@prj-n-cdp-ingestion.iam.gserviceaccount.com" \
  --role="roles/storage.objectAdmin"
8. Give sandbox runtime SA access to sandbox log bucket
gcloud storage buckets add-iam-policy-binding \
  gs://bkt-prj-n-cdp-ingestion-airflow_log-sandbox \
  --member="serviceAccount:sa-kubtogcp-sandbox@prj-n-cdp-ingestion.iam.gserviceaccount.com" \
  --role="roles/storage.objectAdmin"

Verify:

gcloud storage buckets get-iam-policy \
  gs://bkt-prj-n-cdp-ingestion-airflow_dag-sandbox
9. Give GKE/image-pull identity access to sandbox Artifact Registry

First identify the identity currently used by the GKE nodes/workloads.

Then grant:

gcloud artifacts repositories add-iam-policy-binding airflow-sandbox \
  --location=northamerica-northeast1 \
  --member="serviceAccount:<GKE_IMAGE_PULL_SERVICE_ACCOUNT>" \
  --role="roles/artifactregistry.reader"

Do not guess <GKE_IMAGE_PULL_SERVICE_ACCOUNT>.

10. Create sandbox Kubernetes namespace

After identifying the existing GKE cluster:

gcloud container clusters get-credentials <EXISTING_GKE_CLUSTER> \
  --region=northamerica-northeast1 \
  --project=prj-n-cdp-ingestion

Then:

kubectl create namespace airflow-sandbox

Verify:

kubectl get namespace airflow-sandbox
11. Create sandbox Kubernetes ServiceAccount
kubectl create serviceaccount airflow-sandbox \
  --namespace airflow-sandbox

Verify:

kubectl get serviceaccount \
  airflow-sandbox \
  -n airflow-sandbox
12. Connect Kubernetes SA to GCP SA using Workload Identity

Grant the Kubernetes identity permission to impersonate the GCP service account:

gcloud iam service-accounts add-iam-policy-binding \
  sa-kubtogcp-sandbox@prj-n-cdp-ingestion.iam.gserviceaccount.com \
  --role=roles/iam.workloadIdentityUser \
  --member="serviceAccount:prj-n-cdp-ingestion.svc.id.goog[airflow-sandbox/airflow-sandbox]"

Then annotate the Kubernetes SA:

kubectl annotate serviceaccount airflow-sandbox \
  --namespace airflow-sandbox \
  iam.gke.io/gcp-service-account=sa-kubtogcp-sandbox@prj-n-cdp-ingestion.iam.gserviceaccount.com

Verify:

kubectl describe serviceaccount airflow-sandbox \
  -n airflow-sandbox
13. Create sandbox Airflow metadata database

Do not connect sandbox Airflow to the TEST Airflow metadata database.

If using the existing Cloud SQL instance, first inspect it:

gcloud sql instances list

Then inspect databases:

gcloud sql databases list \
  --instance=<AIRFLOW_CLOUD_SQL_INSTANCE>

Create a separate database:

gcloud sql databases create airflow_sandbox \
  --instance=<AIRFLOW_CLOUD_SQL_INSTANCE>

Verify:

gcloud sql databases list \
  --instance=<AIRFLOW_CLOUD_SQL_INSTANCE>

The exact DB user/password/network configuration should follow your existing Canam Cloud SQL setup.

14. Create sandbox Airflow secrets

First inspect existing TEST secrets:

kubectl get secrets -n <TEST_NAMESPACE>

Then create sandbox-specific secrets rather than blindly reusing TEST credentials.

For example:

kubectl create secret generic airflow-sandbox-secrets \
  --namespace airflow-sandbox \
  --from-literal=PLACEHOLDER=PLACEHOLDER

But don't actually use that placeholder command in production.

Use the existing Canam secret-management pattern.

Only the GKE cluster itself can safely be shared with TEST if you use a separate namespace and properly isolate the workloads. Everything else should either be sandbox-specific or explicitly documented as intentionally shared.

I would start with items 1–12 first. In particular, don't deploy the Helm chart yet: first identify the existing TEST GKE namespace, Helm release, KSA, GCP service account, Cloud SQL instance/database, and current Helm values. Those six pieces determine the exact commands for creating the sandbox Airflow runtime without accidentally modifying TEST.
